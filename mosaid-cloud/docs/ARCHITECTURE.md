# Mosaid Cloud — التوافق المعماري مع Mosaid

هذه الوثيقة تشرح كيف يَستنسخ هذا التطبيق (Vercel + Supabase) **المبادئ المعمارية
الأساسية** لمشروع `mosaid` (Go / Android-Termux / Telegram) — لا إعادة كتابة الكود
إذ أنه لا يفطن مادياً، بل تُنقل بروح الأمان والتحكم.

> **خلاصة:** "الوكيل السحابي" = فكرة Mosaid ذاته، لكن مُستضافة على Vercel + Supabase
> بحيث تعمل في **متصفح التليفون** مباشرة بدل الاعتماد على Termux، ومع الحفاظ على
> قواعد fail-closed والموافقة والذاكرة والتدقيق.

---

## 1) لماذا Vercel + Supabase بدل Termux؟

| | Mosaid (Termux/Android) | هذا (Vercel + Supabase) |
|---|---|---|
| تثبيت | حزمة تليفون + Termux + Bot | رفع على المنصة + 4 متغيرات |
| تشغيل | على جهازك المحلي | في السحابة — من أي متصفح |
| إدارته | أوامر `/...` عبر تليجرام | واجهة ويب (موبايل/حاسوب) |
| قاعدة البيانات | ملفات `sqlite` محلية | Supabase Postgres (سحابي) |
| الإعداد | `install-phone.sh` + إجابات | لوحة المتغيرات في Vercel |
| المخاطرة | نفق على الجهاز، خادم محلي مكشوف | `AGENT_ACCESS_CODE` + RLS |

الأختيار منك: صرحت أنك تريد **"نفس الفكرة على Vercel و Supabase"**. هذا يُقدَّمها لك.

## 2) مبادئ Mosaid المنقولة

### 2.1 الموافقة الفردية (internal/approval)
- **طلب** يُخزَّن بـ `token_hash` فقط (لا توكن دائماً) في `approval_requests`.
- **مربوط** بـ: `tool_name` + `args_hash` + `resource`.
- **TTL** (`expires_at`) — ينتهي تلقائياً.
- **استخدام مرة واحدة** عبر جدول `approval_uses`.
- **تدقيق** كل خطوة (طلب/قرار/تطبيق) في `audit_log`.
- في هذا الـ Cloud: `lib/core/approval.ts` يطابق ذلك بشكلٍ متوازٍ، وتُستنسخ النتيجة.

### 2.2 الذاكرة (internal/memory)
- **رفض أي نص يشبه سر** (regex في `lib/core/redact.ts`).
- **مرشّحة** (`memory_candidates`) → **موافقة** → **عنصر** (`memory_items`) → فهرسة `tsvector`.
- **البحث** عبر `plainto_tsquery`/`ilike` في دالة Postgres `memory_search`.
- **`forget`/`export`** آمنان.

### 2.3 فحص الإعدادات (fail-closed)
- `checkSetup()` في `lib/core/failclosed.ts` يرفض التشغيل فوراً لو ناقص متغير
  أساسي (`NEXT_PUBLIC_SUPABASE_URL`, key, مفتاح الموديل). الواجهة تستجيب بـ 501.
- حدّ التكلفة `MAX_COST_TRIPWIRE_USD` يبقى قفلاً، مع **سياسة free-only** عبر Gemini.

### 2.4 التدقيق، حجب الأسرار
- كل قرار/طلب/كتابة يذهب إلى `audit_log`.
- `redact()` يستبدل أنماط المفاتيح/التوكن قبل أي تسجيل أو عرض.
- السجلات لا تحوي أبداً مفاتيح خام.

### 2.5 المهارات المنفصلة (skills/)
- `getSkills()` في `lib/agent/skills.ts` يسجّل مهارات منفصلة (عملاء، مشاريع، مهام،
  فلوس، ذاكرة، ترميز). لإضافة مهارة: أضف أدواتها في `tools.ts` ثم سجّلها في
  `getSkills()` دون لمس النواة.

## 3) البنية

```
موبايل/حاسوب (متصفح)
        │
   Vercel (Next.js 15 + AI SDK)
        │  ├── /api/agent     (عقل الوكيل: نموذج + أدوات + مهارات)
        │  ├── /api/approvals (قرار الموافقات + application)
        │  ├── /api/memory    (remember/search/forget)
        │  ├── /api/metrics   (أرقام العمل)
        │  └── /api/status    (صحة النظام)
        │
   Supabase (Postgres)  ──  clients, projects, invoices, tasks, expenses,
        │                       approval_requests, approval_uses,
        │                       memory_candidates, memory_items,
        │                       audit_log, messages
        │
   نموذج الذكاء  ──  Gemini (free tier) عبر OpenAI-compatible endpoint
```

## 4) ما الذي يمكن عمله الآن (بصدق)

- **Read/write داخل قاعدة البيانات:** نعم (عملاء/مشاريع/مهام/فواتير مسودة/مصاريف/ذاكرة).
- **موافقات على أفعال خارجية:** نعم عبر `submit_approval` (في انتظار موافقتك).
- **إرسال بريد/واتساب حقيقي:** **ليس بعد** — مُحاكى (يُسجَّل الحالة). ربط المزوّد
  يتطلب حساباً + اعتبارات أمان/خصوصية، وهو خطوة لاحقة (اختيارية).
- **ذاكرة دائمة:** نعم (FTS + رفض أسرار + مرشّحة→موافقة).
- **سجل تدقيق كامل:** نعم.

## 5) الأمان / الحدود (غير قابلة للتفاوض)

- `AGENT_ACCESS_CODE` يحمي كل واجهة API.
- لا تُخزَّن أسرار خام داخل تطبيق أو سجل؛ تُحقن عبر متغيرات البيئة.
- **لا تضعبي بيانات حساسة** (كلمات سر، بيانات بنكية كاملة) في المحادثات نفسها —
  فالمزود المجاني يمكن أن يستخدمها لتحسين نماذجها.
- **بُعد الشرح** الصحيح القادم من `README.md` و `.env.example`.
