# Mosaid Runtime Pivot — Hermes on Oracle Cloud

Date: 2026-07-29
Status: Accepted

## Decision

Mosaid will use `NousResearch/hermes-agent` as its single general-purpose agent runtime. Oracle Cloud Compute will host that runtime. Mosaid will remain the product layer: Arabic identity, beginner guidance, digital-work Work Packs, portfolio/opportunity/client workflows, zero-cost policy, approvals, safety rules and product-specific evaluation.

There will not be a Go Mosaid runtime running beside Hermes. One runtime avoids duplicate agent loops, Telegram gateways, model routers, memory stores, schedulers, MCP clients and skill loaders.

## Layer separation

These four layers are distinct and are not substitutes for one another:

| Layer | Role | Choice |
|---|---|---|
| Hosting and compute | The billed machine that exists | **Oracle Cloud Compute** |
| Agent runtime | Agent loop, gateways, memory, Skills, tools | **Hermes Agent** (pinned) |
| Product | Identity, Arabic behavior, policy, approvals, Work Packs | **Mosaid** |
| Execution sandbox | Isolation for untrusted code | **none in First Gate** |

Oracle is the host and is not replaced by any runtime or sandbox technology. There is no fourth layer active today: the First Gate runs with no execution sandbox at all. Docker — already supported inside Hermes — is the first isolation option to consider after a successful launch, and AgentENV is a deferred, optional, conditional later stage. See [`AGENTENV-EXECUTION-BACKEND-DECISION.md`](AGENTENV-EXECUTION-BACKEND-DECISION.md) for the full rationale and adoption gate.

## Why

Hermes already provides the capabilities that Mosaid was rebuilding:

- model-provider switching without product-code changes;
- Telegram and other messaging gateways;
- persistent memory and conversation search;
- Skills and Agent Skills compatibility;
- scheduled jobs;
- MCP integration;
- local, SSH and cloud execution backends;
- Termux support;
- a learning loop and skill drafting;
- MIT licensing.

The stopped prototype in PR #3 demonstrated useful product ideas and safety fixes, but its new cognitive engine and router were still not wired into `cmd/mosaid/main.go` or `internal/agent/agent.go`. Continuing that implementation would duplicate an existing mature runtime.

## Target architecture

```text
Telegram / phone
      |
      v
Oracle Cloud Compute            <- hosting and compute
      |
      v
Hermes Agent runtime            <- the one and only agent runtime
      |
      +-- Mosaid identity and Arabic behavior
      +-- Mosaid policy and approval profile
      +-- Mosaid Work Packs and Skills
      +-- Mosaid portfolio/opportunity/client workflows
      +-- approved model provider or self-hosted endpoint

No execution sandbox layer is active in the first release.
```

## Security boundaries

Hermes features are not enabled wholesale. Mosaid applies a restricted profile:

0. No code execution runs in the first gate; `terminal`, `file`, `code_execution`, `browser` and `computer_use` are globally disabled, so no sandbox technology is required yet.
1. Tools are deny-by-default and explicitly allowlisted.
2. External Skills are data until reviewed, pinned, tested and approved.
3. Skill self-improvement produces a draft only; it never self-activates.
4. High-risk actions require owner approval.
5. No free-form remote command generated by a model is executed without a typed tool boundary and policy check.
6. Secrets are file references or environment-injected values, never committed.
7. Oracle account credentials are not stored in Mosaid. Runtime access uses SSH keys and a dedicated service secret only when needed.
8. The default billing mode is free-only with a zero spend ceiling and no paid fallback.

## Upstream policy

- Pin an exact Hermes commit before deployment.
- Record the upstream commit, license and dependency lock state.
- Review updates before adoption; no unattended self-update.
- Keep Mosaid customizations outside upstream files where practical.
- Contribute generic fixes upstream rather than maintaining unnecessary forks.

The same pin discipline applies to any future execution backend. The current reviewed pin is recorded in [`HERMES-UPSTREAM-PIN.md`](HERMES-UPSTREAM-PIN.md) and is not changed automatically.

## Repository policy

- PR #3 remains closed and unmerged as prototype evidence.
- Its branch and commits remain immutable and available for selective migration.
- The current Go foundation on `main` remains historical product evidence until the Hermes-based runtime passes acceptance tests.
- No destructive archive or deletion occurs during the pivot.

## Acceptance gate

This pivot is complete only after all of the following are demonstrated on the Oracle instance:

- Hermes starts from a pinned upstream commit.
- Telegram owner-only communication works.
- A model endpoint answers through the selected free-only configuration.
- Mosaid identity and Arabic behavior load automatically.
- Tool allowlists and approval gates block unauthorized actions.
- At least one Mosaid Work Pack runs end-to-end.
- Restart preserves the session and unfinished work.
- Secrets are absent from Git, logs and diagnostic bundles.
- A rollback procedure restores the previous working deployment.
